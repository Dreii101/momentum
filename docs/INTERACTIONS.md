# Shared interaction conventions — Phases 3–10

- Settings → Reminders is the opt-in reminder surface. Enable requests notification permission in context; exact alarms are a separate optional Android action. Test notification acknowledges a request without claiming delivery. Denied/approximate/unavailable access never blocks core features.
- Rules select an existing deadline, activity series, work block or installation timer endpoints. Save preserves the source; disabling cancels its triggers. Quiet-hour drafts survive resizing and errors. Retry scheduling never resaves or rolls back a task. Actual scheduled-through, checked horizon and capacity omissions are separate labels.
- Notifications open original current records after revalidation. Stale sources show a dismissible message in Reminders, reached through the shell attention icon. Elapsed/opening-unconfirmed is not seen/delivered. No overdue catch-up notifications or automatic timer/task completion occur.

- Today Start/task Prepare a two-minute start opens setup; choose the saved next action or an incomplete step, then explicitly Start for 2 minutes. General/task focus has 10/25/50/custom choices; Ctrl+Enter starts from setup. Start never follows navigation automatically. Suggestions remain optional.
- Large session controls pause/resume, add five minutes or end for review. Footer Return to session works after opening tasks/notes or changing destinations. Countdown repainting makes no database writes and no automatic per-second screen-reader announcement. Hidden/paused countdown displays do not run unnecessary repaint callbacks.
- Review requires a whole-second work amount (zero is valid) and confirmation. Saved means finalized in SQLite. Errors retain input with Retry. After a saved starter review, Continue 10/25 or Custom, Mark step done and Stop here are deliberate choices; break preparation is also explicit. No timer interval completes anything automatically.
- Explicit whole-task completion ends its running/paused session for uncredited review before changing the task status. Deleted task links remain identifiable; review/history stay available. A pending session blocks replacement with a Return to session explanation.
- Recent sessions shows the latest 20 saved reviews by their original IDs and kinds. Progress summaries/reflections and OS reminders remain later phases.

- Development's Timer engine controls use real workspace sessions and display only confirmed database state. Keep Running, Paused, Awaiting review and Finalized distinct. Errors retain inputs and the last confirmed state with Retry. Reported work requires an explicit amount and confirmation; zero is valid. Neither elapsed time nor review completes tasks or steps.
- Background/restart/clock uncertainty stays visible and is excluded from eligible work. A recovered session requires review and never starts itself. Screens observe an installation-owned coordinator; navigation does not start, stop or recreate it. The production footer and starter/focus journey connect in Phase 9.

- Plan opens the unified calendar, with Timetable & courses retaining schedule tools. Android defaults to Agenda; Windows to Week and a wide selected-item panel. All Day/Week/Agenda choices, filters and date navigation use accessible controls. Hidden subpages are excluded from focus traversal.
- Deadline/target/class/work labels and icons communicate type without relying on color. Date-only deadlines stay on the written date with their own zone. Moved classes occupy their effective slot; cancellation is an explicit filter. Overnight items retain one identity across day columns.
- Work uses forms: choose task, start/zone, preset/custom elapsed length, status and lock; Save/Ctrl+S commits. Warnings allow deliberate overlap after acknowledgement. Remove/Restore affects only the work record; no deadline or estimate changes. Work completion gives no focus credit or task completion.
- Calendar details open the original task/activity. Task estimate and internal target remain optional. Work drafts keep text/selection through resizing/theme changes; failed saves keep fields with Retry. Saved records are durable; transient unsaved forms are not promised across process termination.

- Plan offers daily Android and weekly Windows timetables plus course management. View date is in the planning zone; activity details show the original zone. Weekly columns scroll horizontally when space or enlarged text requires it.
- Course/activity forms save explicitly. Activity Preview/Ctrl+S reviews the first 14 days and any affected future exceptions/notes before Save. Editing invalidates that preview. Detected overlaps require a deliberate acknowledgement and remain allowed. Failed saves retain fields.
- Cancellation/rescheduling applies to one original occurrence. Restore cancellation keeps its rescheduled location/time; Reset returns it to the original schedule. “This and future” explains its original-date boundary and retained links before a transaction. Superseded history remains linked and accessible.
- Keep note relationship controls secondary to writing. Whole-series and original-occurrence scopes are labelled; both open the original note. Archiving a course preserves all content and meetings. There are no required courses.

- Notes starts with an empty page; title and body are optional. Autosave waits about 500 ms after editing. Save note/Ctrl+S flush immediately. Keep Saving, Unsaved changes, Saved on this device and Couldn’t save distinct; never report success before commit.
- A note keeps one text/selection buffer across navigation, resize and theme changes. Typing continues while a save is pending. Errors retain the exact draft with Retry/Copy; hidden unsaved drafts have Review/Copy in the shell, including a storage opening failure. Unsaved memory is not promised after process termination.
- Notes uses focused mobile flow and wide Windows library/editor panes. Pin/course and task links stay below writing. Search matches literal title/body text. Empty titles display Untitled note; empty bodies are valid. Limits count Unicode code points, and over-limit text stays available to copy/shorten.
- Note Trash first saves pending writing; a failed save prevents removal. Show Trash and Restore recover the original note with its links. Linked task/note entries open original IDs, including clearly labeled trashed records. Unlink removes only the association; deleting a task never deletes its notes.

- Tasks uses title-only capture, common editing fields first and an optional planning disclosure. Save task/Ctrl+S means committed to SQLite. Failed saves preserve all text; switching task records keeps unsaved drafts in memory. Save before closing the app.
- Windows splits the task list/detail at >=1000 logical pixels; narrower Windows and Android show one pane with Task list/Android Back. Returning from Today selects the same task record. Sidebar navigation has grouped keyboard traversal.
- Today’s choices are manual, at most three for the current planning-zone date. Start opens the next-action area without claiming a running timer. A completed choice remains visibly completed. No schedule entries are invented.
- Use explicit time-zone labels for deadlines and internal targets, ISO dates and 24-hour time. Date-only means the whole date in its stored zone. Repeated/skipped local times require another time or unambiguous UTC; failures keep input.
- Archive, Trash and completion are independent. Archive/Trash offer Undo, and list filters expose Unarchive/Restore. Restoring retains notes/steps and does not silently reselect Today priorities.
- Subtask ordering uses accessible Up/Down controls. Completing all steps offers whole-task completion. Removed steps are restorable from their disclosure.

- Widths use available logical pixels: <600 bottom navigation, 600–999 rail, >=1000 sidebar and detail slots. Keep one keyed destination subtree through these changes; never use the navigation layout as an editor's identity.
- Today, Tasks, Plan and Notes are primary. Progress and Settings live in Android's menu and Windows' rail/sidebar. Compact Windows falls back to the menu. Extra destinations do not falsely select a primary tab.
- Route selection and per-destination record IDs belong to ShellNavigation. Editors added later must preserve their draft identity under the existing page key or a record-scoped provider. Current Settings drafts and per-page scroll offsets survive switching destinations and resizing.
- Use neutral Material surfaces, restrained teal and system fonts. Body text is 16 logical pixels with readable line height. Use Space tokens: 4/8/12/16/24/32. Let labels wrap; do not clamp user text scaling. Pages and navigation scroll when necessary.
- Buttons, menu items, fields and primary navigation have at least 48-pixel touch targets. Keyboard focus must remain visible; inputs and buttons use focus borders. Tab/Shift+Tab traverse controls, Enter/Space activate them, and inactive pages are excluded from traversal.
- Settings uses a local draft and explicit Save changes. Ctrl+S works while focus is inside that form. Validate all fields before one repository command. A failed save retains the draft, exposes details and offers Retry. Show Saved only after commit; unsaved edits are not promised across process termination.
- Theme and reduced motion apply after saving. System follows device appearance. Either app or device reduced motion disables theme/diagnostic transitions; navigation changes immediately. Loading always has a readable label and uses a static indicator when motion is reduced.
- Distinguish loading, empty, no results and failure. Future routes state that their tools are coming; never show invented tasks, sessions or totals. Do not turn storage errors into empty lists. Use the shared recovery component and retain drafts where possible.
- Error details use local disclosure state, separate from scroll-position storage. Give every page scroll view a stable, distinct storage key.
- The session footer is a single shell-level host connected to the durable coordinator. It opens the current session/review or setup; changing destinations never restarts that timer.
- Preserve native Windows controls and resizing behavior. Do not add frameless-window code or duplicate operating-system controls.
